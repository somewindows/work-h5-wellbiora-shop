# 订单流程与状态机设计

> 阶段 B 技术设计文档。覆盖：下单时序、订单状态机（君梦状态 → 前端展示映射）、
> 取消窗口、三单对碰与限额校验时机。
> 君梦接口细节见 `docs/vendor/junmeng/`，对接注意事项见 `junmeng-integration-notes.md`，本文不重复。

## 一、下单支付时序（支付先行）

君梦下单接口要求**先有成交通行的微信支付单号**（`payId`，财付通备案号 4403169D3W），所以时序是：

```
用户提交订单
  → 服务端：本地校验（实名/限额/库存/三单对碰）→ 创建本地订单（待支付）
  → 服务端：向微信下单（JSAPI/Native prepay），拉起支付
  → 用户支付 → 微信支付回调（异步，唯一可信的支付成功来源）
  → 服务端：回调内推君梦 jm.order.bonded.add（带支付单号）
  → 君梦申报海关 → 轮询 jm.order.bonded.get 同步履约状态
  → 发货信息由「发货接口」回传（我方需提供公网 HTTPS 回调地址，待确认）
```

要点：

- **支付成功以微信回调为准**，不以前端页面跳转为准；回调要验签、幂等（同一回调可能重复推）。
- 支付超时（建议 30 分钟）未付 → 本地订单关闭，不占用任何下游资源。
- 支付成功但推君梦失败 → 进人工/自动重试队列，**绝不静默**；多次失败则触发退款流程并告警。
- 防重复提交：提交订单接口幂等（客户端带唯一请求号，或服务端按「用户+商品+时间窗」去重）。

## 二、订单状态机

### 2.1 三层状态，各管各的

| 层 | 状态来源 | 说明 |
|---|---|---|
| 本地主状态 | 我方 DB | 用户看到的唯一状态，由下面两层推导 |
| 支付状态 | 微信支付回调 | 待支付 / 已支付 / 已退款 / 退款中 |
| 履约状态 | 君梦轮询 + 发货回调 | 君梦状态枚举原样存储 |

### 2.2 君梦状态枚举 → 前端展示映射

君梦 `orderInfoStatus`（见 `jm.order.bonded.get-订单查询接口.md`）：

| 君梦状态 | 含义 | 前端展示 |
|---|---|---|
| 0 待审核 / 3 待支付 / 10 处理中 | 订单在 OMS 内部流转 | 待发货 |
| 15 清关中 | 海关申报中 | 待发货（标签：清关中） |
| 20 清关完成 / 30 已下发仓库 / 35 已打单 | 拣货打包阶段 | 待发货 |
| 40 订单出库 / 70 揽收 | 已有物流单号 | 待收货 |
| 100 签收 | 履约完成 | 已完成 |
| 50 订单取消 / 81 已撤单 / 91 已退货入区 | 履约终止 | 已取消 |
| 80 待撤单 / 90 待退货入区 | 取消/退货流转中 | 退款处理中 |

- **君梦原始状态码原样落库**（不丢信息），映射表只做展示层，后期调映射不改数据。
- 前端「已取消」是原型验收时补的展示态，映射逻辑以此表为准。
- 状态同步只有**轮询**一条路（君梦无状态推送）：待发货订单加密轮询（如 30 分钟），待收货订单日级轮询，签收后停止。发货回调到达时立即触发一次查询收敛状态。

## 三、取消与退款窗口

| 时机 | 能否取消 | 动作 |
|---|---|---|
| 待支付 | 可 | 直接关闭本地订单，无资金动作 |
| 已支付、未推君梦 | 可 | 微信原路退款，订单关闭 |
| 已推君梦、未申报 | 可（API） | 调 `jm.order.bonded.cancel` + 微信退款 |
| 已申报（清关中起） | **不可 API 取消** | 前端引导联系客服，走人工拦截/拒收退货流程 |
| 出库后 | 不可 | 只能收货后售后；售后接口君梦侧「开发中」，MVP 期客服人工处理 |

- 取消窗口的判断依据 = 本地记录的君梦履约状态，不要用「下单至今的时间」猜。
- 所有资金退回一律**微信原路退回**，不做余额、不做线下转账。

## 四、下单硬校验（服务端强制执行，前端只做提示）

对应 AGENTS.md 硬性规则 2 / 6：

1. **实名认证**：姓名 + 身份证号，格式校验 + 与收货人一致性校验；身份证仅存密文/脱敏展示。
2. **单笔 ≤ 5000 元**：订单应付金额（含税费）超 5000 直接拒单，购物车页提前提示。
3. **个人年度累计 ≤ 26000 元**：按身份证号累计本年度已申报金额；本地累计只是预检，**海关拦截才是终审**——被拦订单从君梦 `systemRemark`（拦截信息）体现，前端展示「海关退单」并自动触发退款。
4. **三单对碰**：订购人（实名信息）、支付人（微信支付实名）、收货人必须一致。校验点在下单时：收货人姓名须与实名姓名一致；支付人一致性以微信回调的支付信息为准，不一致则自动退款关单。

## 五、异常与对账

- 每日对账：微信账单 vs 本地订单 vs 君梦订单三方核对，差异进人工处理清单。
- 君梦轮询发现本地没有的终止状态（如仓库侧直接取消），以君梦为准收敛本地状态并触发退款核查。
- 所有状态变更留审计日志（谁触发、原状态、新状态、来源：回调/轮询/人工）。

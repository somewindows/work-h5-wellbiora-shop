# 支付申请与资金流说明（1210 保税模式 · 以微信支付为例）

> 整理日期：2026-08-26。本文回答三个问题：①微信支付怎么申请、申请完是不是就能收款；②用户付的钱在哪；③1210 保税/海关环节涉及的资金动作。
> 信息来源：微信支付官方文档与商户平台说明（文中附链接）+ 君梦 OpenAPI 2.0 文档。**涉及费率、审核口径的内容以申请时微信官方最新规则为准**；与君梦/保税仓相关的结算细节以商务确认为准（见文末待确认）。

## 一、微信支付商户号申请流程

申请入口：[pay.weixin.qq.com](https://pay.weixin.qq.com)（注册 → 提交资料 → 审核 → 签约）。

**所需资料**（企业主体；个体工商户略有差异）：

- 营业执照（彩色扫描件/照片，三证合一）
- 法人身份证正反面
- 对公银行账户（开户行、账号、分支行信息）
- 联系人手机号、邮箱
- 已有微信公众号/小程序的 AppID（用于绑定支付场景，见下）

**流程**（参考[凡科/金数据等接入指引](https://help.jinshuju.net/next/articles/wxpay/)）：

1. 提交资料 → 微信审核约 1~2 个工作日（部分情况要求**对公账户小额打款验证**）
2. 审核通过 → 超级管理员签署协议（手机签约或网银签约）
3. 获得商户号（mchid）→ 登录商户平台配置

## 二、申请下来 ≠ 就能支付

商户号只是「收款账户主体」，**支付能力按「产品」逐个开通**，对应我们的 H5 场景：

| 产品 | 场景 | 本项目 | 备注 |
|---|---|---|---|
| **JSAPI 支付** | 微信内浏览器（公众号内 H5） | **必须开通** | 需绑定**认证服务号**的 AppID；支付授权目录要配置已备案域名 |
| **H5 支付** | 微信外手机浏览器（Safari/夸克等） | 视渠道决定 | 单独申请，审核较严，需描述实际经营场景 |
| Native 支付 | PC 扫码 | 不需要 | — |
| 退款 | 原路退回 | 必须 | 默认随商户号可用，注意退款接口权限与证书 |

> 即：**用户在微信里打开商城 → 走 JSAPI；在普通浏览器打开 → 走 H5 支付**。前端要判断运行环境分流（这是之前「坑清单」里的第 1 条）。

其他必做配置：API v3 密钥、商户 API 证书（回调验签/退款用）、支付授权目录、支付回调 URL（公网 HTTPS）。

**费率与结算**：常规类目费率约 0.6%（以签约类目为准）；结算周期通常 **T+1**，新商户可能有更长的「新手期」结算限制。

## 三、用户付的钱在哪（资金流）

```
用户微信钱包/银行卡
        │  支付
        ▼
财付通 · 微信支付商户号账户（我们的 mchid）   ← 钱先停在这里，不是直接到银行卡
        │  T+1 自动结算（扣除手续费后）
        ▼
公司对公银行账户
```

- 支付成功时，资金在**财付通侧我们商户号的账户余额**里，商户平台可见流水与余额。
- 按结算周期（T+1）自动划转到绑定的对公账户；手续费从结算款中扣除。
- 退款从商户号余额/结算款中原路退回用户，**已结算的钱退款时要保证余额充足**（可在商户平台预留退款备用金）。

## 四、1210 保税/海关环节的资金动作

**核心认知：海关不管消费资金，只管「信息流」的三单对碰**。涉及钱的动作其实只有两条线：

### 1. 支付单推送海关（信息流，不含资金划转）

三单对碰 = 订单（我们 → 君梦 → 海关）+ **支付单（财付通 → 海关）** + 运单（仓库/物流 → 海关）。

微信支付侧的海关报关能力（[微信支付跨境开发者中心](https://pay.weixin.qq.com/doc/global/v3/zh/4013025127)）：

- 先决条件：在商户平台提交**海关备案信息**（[订单附加信息提交接口说明](https://pay.weixin.qq.com/doc/v2/merchant/4011985151)：所有要报关的海关都要先提交，真实有效）；并在「产品中心 → 自助清关」申请开通
- 支付完成后调「订单附加信息提交/报关」接口，以**商户订单号 out_trade_no + 微信支付订单号 transaction_id + 实付人民币金额**向海关申报支付单
- 丢单可用「报关重推」接口补推；状态可查「报关查询」
- 君梦下单接口里的 `payId = 4403169D3W`（财付通海关备案号）就是告诉海关「支付单由财付通推送」——两边对得上，三单才能碰

### 2. 跨境综合税（真资金，商家侧支出）

- 我们页面对用户承诺「税费商家承担」，即用户到手价含税。
- 实际缴纳：1210 模式海关按申报清单征收跨境电商综合税，**由电商企业（我们）缴纳**；实操中多由保税仓/报关行**代缴后与我们结算**，或要求**预存税金/保证金**按清单核销——具体模式问君梦/义乌保税仓商务。
- 粗算口径（以最终海关核定为准）：跨境综合税 ≈（关税 0% + 进口环节增值税/消费税按法定 70% 征收），保健品多在 **9.1%** 左右（增值税 13%×70%）——定价时这笔成本要算进去。

### 3. 保税仓/君梦费用（商家侧支出，与消费者资金流无关）

仓储费、订单操作费、包材、快递费等，与君梦/仓库按商务合同结算（通常月结或预存）。与消费者支付链路完全独立。

### 4. 退款时的海关处理（信息流）

- 资金：微信支付退款接口原路退回用户。
- 海关：**未申报**的清单可由君梦 API 直接取消；**已申报**的清单须联系仓库线下做清单作废/改单（见 `docs/tech/junmeng-integration-notes.md` 第 13 条）。退款的产品设计要区分这两个窗口。

## 五、一页纸总览

```
【消费者资金】  用户 ──支付──▶ 财付通商户号 ──T+1 结算──▶ 对公账户
【信息流-海关】  我们(订单) + 财付通(支付单) + 仓库(运单) ──▶ 海关三单对碰 ──▶ 放行
【商家支出】    综合税：海关 ◀──（我们或仓库代缴，按清单结算）
                仓配费：君梦/仓库 ◀── 月结/预存
【退款】        财付通原路退回用户；已申报清单需仓库线下改单
```

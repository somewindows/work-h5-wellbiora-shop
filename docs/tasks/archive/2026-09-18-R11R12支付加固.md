## 改动内容

### R12：V3 应答验签 + 请求超时 + 关联字段核对

- `server/src/payments/wechat-pay.client.ts`
  - 新增 `WechatPayResponseSignatureError`；`request()` 对**成功应答**强制验签后才采信（验签串 = `Wechatpay-Timestamp\nWechatpay-Nonce\n应答体\n`）。公钥模式用 `config.publicKeyPem` 验且 serial 必须 = publicKeyId；平台证书模式用缓存证书验，未命中先刷新一次再验。唯一豁免：`GET /v3/certificates` 应答在本地无对应序列号证书时按微信官方指引跳过（鸡生蛋问题；证书内容另有 APIv3 密钥 AES-GCM 解密兜底）。
  - 请求超时兜底：AbortController + `WXPAY_REQUEST_TIMEOUT_MS`（默认 15000，≥1000 整数，config 加载器校验）。评审建议修复：**`response.text()` 读完前不 clearTimeout**，慢滴漏 body 也在超时窗口内。
  - 错误响应（!response.ok）不验签（仅作诊断信息，最坏是被降级拒绝服务，无法伪造资金入账）。
- `server/src/payments/wechat-payment.adapter.ts`
  - `queryPayment` 核对应答关联字段：`out_trade_no` 精确相等、`mchid` 必须存在且等于配置、`appid` 若返回必须相等；不符抛 `BusinessException(40002)` 拒绝采信（评审建议：普通 Error 会让管理员手动同步看到 500，包成业务异常透出可读原因）。
  - `queryRefund` 补 `out_refund_no` 核对（评审建议，与查单同口径纵深防御）。
- `server/src/payments/wechat-pay.config.ts`：新增可选 `requestTimeoutMs`；`server/.env.example` 补 `WXPAY_REQUEST_TIMEOUT_MS` 注释行。

### R11：平台证书刷新防护（仅平台证书模式可达，生产公钥模式不受影响）

- `refreshPlatformCertificates()` 加：single-flight（并发伪造回调共用同一次刷新）+ 最小间隔 60s + 失败指数退避（60s·2^(n-1) 封顶 15min）；原刷新逻辑移入私有 `doRefreshPlatformCertificates()`。
- 评审建议修复：**一张证书都没能入库（典型 = APIv3 密钥配错）按刷新失败处理**，否则退避永不生效、伪造回调可维持每 60s 一次真实刷新。
- 回调语义不受影响：`verifyNotification` 刷新失败/被限流仍回 false → 控制器 4xx → 微信按节奏重推（最长约 24h ≫ 退避上限 15min），合法证书轮换可自愈。

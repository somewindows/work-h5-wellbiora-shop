# 归档：商品 ID 规范化（p1~p4 → WB10001~WB10004）

- **日期**：2026-09-03
- **背景**：商品 ID 沿用原型占位 `p1`~`p4`，不规范且已进入正式表结构（`catalog_products.id`）。趁尚无真实订单（ID 未快照进订单数据）完成切换。

## 规范约定（后续新增商品必须遵循）

- 商品 ID = 品牌前缀 `WB` + 5 位递增数字，自 `WB10001` 起
- 不重复保障：发放时事务内取当前最大序号 +1；数据库主键唯一约束兜底
- 将来多规格时规格码挂后缀（如 `WB10001-01`），不影响主编号
- 保税仓 `goods_no`（`catalog-product.entity.ts` 的 `goodsNo` 字段）是君梦仓库分配的编码，仅做映射，与本 ID 不混用

## 改动范围（17 个文件）

- `server/src/catalog/catalog.seed.ts`（种子 id + productIds + PRODUCT_DETAILS 键）
- server 6 个单元测试 spec + 6 个 e2e spec 中的商品 ID 与 URL 片段
- `frontend/mock/` 的 products/home/orders/misc 四个 mock 文件
- 图片资源文件名（`p1-main.jpg` 等）**未改**，仅 ID 字段变更；`prototype/` 静态原型按约定未动

## 验证结果

- server 单元测试 66/66、e2e 36/36 通过
- frontend Vitest 11/11 通过

## 遗留点

- LOCAL_TEST_MODE 内存模式重启后自动以新 ID 播种；正式 MySQL 库若已播种过旧 ID，需清库重播或手工 UPDATE（当前正式库未启用，暂无操作）
- `prototype/app/` 静态原型仍是 p1~p4 演示数据，与工程代码无耦合，如后续维护原型可顺带更新

## 产出

**R08 对账依据落库**
- orders 加 `payer_total_fen`（用户实付，分）+ `pay_currency`（微信 amount.currency，国内直连与 payer_currency 恒一致）两列，迁移 `1710000014000`（便携 MySQL run/revert/run 已验，历史单为 NULL）
- 写入点收口在**同一条件更新**内（markPaidIfPending / registerLatePaymentIfCancelled fields 扩展），四条支付事实登记路径口径一致：正常回调 / 迟到扣款 / sync-payment 查单 / mock-pay（mock 落总额+CNY）
- 回退与告警：微信缺省 payer_total 按总额记（优惠额自然为 0）；currency 非 CNY、payer_total > total 仅 warn 照常落库；amount.total vs total_fen 硬拒绝不动
- **优惠额不落库**（设计决策）：导出/详情展示时按 `total_fen - payer_total_fen` 派生，避免冗余列口径漂移
- 后台订单详情透出「用户实付（含币种）/ 优惠额」

**admin 订单导出 CSV**
- `GET /admin/orders/export`（声明在 `:orderNo` 之前；@Res 直写绕开响应壳拦截器），复用订单列表全部筛选条件，封顶 10000 行
- 列：订单号/订单状态/支付状态/订单总额/用户实付/优惠额/币种/支付时间/微信交易号/收件人姓名/手机号(脱敏)/创建时间；BOM + 中文状态标签 + 分转元；审计 `export_orders`（filters + count + truncated）
- **CSV 公式注入防护**（对抗性评审抓出）：自由文本以 `= + @ \t` 开头（`-` 后跟非纯数字也算）前缀 `'`
- 截断可感知：达到封顶时 logger.warn + 审计记 `truncated: true`
- 前端：request.ts 加 blob 直通（错误体解析 JSON message，401 仍跳登录），列表页「导出 CSV」按钮（axios blob + createObjectURL，revoke 延时 1s 兼容 Firefox）

# 2026-09-11 新建商品 ID 改为服务端自动生成

## 背景

2026-09-03 商品 ID 已规范化为 WB + 5 位递增数字，但后台「新建商品」仍是旧逻辑：运营手填 ID，校验规则还是「小写字母开头，仅小写字母/数字/中划线」。截图确认后改为服务端自动生成。

## 改动

- `server/src/admin/dto/create-admin-product.dto.ts`：删除 `id` 字段（客户端不再提交）。
- `server/src/catalog/catalog.repository.ts`：`CatalogRepository` 新增 `nextProductId()`，TypeORM 与内存实现一致——取 10001 起最小未占用编号（`computeNextProductId`），删除商品后编号可回收复用（填坑策略，满足「删除后不再占用」的要求）。
- `server/src/admin/admin-catalog.service.ts`：`createProduct` 用 `nextProductId()` 生成 ID，删除重复 ID 校验。
- `admin/src/types/index.ts` + `admin/src/views/products/ProductListView.vue`：新建对话框去掉手填 ID 项，改为静态提示「由服务端自动生成」；创建成功提示中展示分配到的 ID。
- 测试：单测覆盖递增与「中间编号删除后填坑」；e2e 原先手填 `p9` 的用例改为捕获服务端分配的 ID（WB10005/WB10006）。

## 验证

- 服务端单测 107/107、e2e 39/39、lint、生产构建通过
- admin `vue-tsc --noEmit`、`vite build`、vitest 21/21 通过

## 遗留点

- 目前后台没有「删除商品」功能（只有上下架），编号回收逻辑已就绪，待删除功能落地后自然生效。历史订单的 order_items 存的是快照（name/spec/priceFen 等），复用编号不影响历史订单展示。

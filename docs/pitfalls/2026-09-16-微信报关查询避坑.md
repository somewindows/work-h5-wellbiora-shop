# 2026-09-16 微信报关（自助清关）查询避坑清单

> 读者：改动 `server/src/payments/wechat-customs.service.ts` 或排查报关异常（EXCEPT/FAIL）的 agent。
> 每条 = 规则 + 出处（真实踩坑）。自助清关 V2 接口文档：申报 https://pay.weixin.qq.com/doc/v2/merchant/4011985151 ，查询 https://pay.weixin.qq.com/doc/v2/merchant/4011985273 。

## 查询接口（customdeclarequery）

- **`customs` 是必填参数**：和申报接口一样要传海关代码。漏传时微信返回 `result_code=FAIL` + `customs invalid`，**报错文案不提示是哪个参数缺失**，极易误判成「海关代码配错/备案没生效」。（事故：2026-09-16 后台报关查询上线后真实环境报 customs invalid，实际是 queryDeclaration 漏传 customs。）已固化在 queryDeclaration + 单测（断言请求体含 `<customs>`）。
- **成功应答的记录字段带序号后缀**：`state_0` / `cert_check_result_0` / `explanation_0` / `modify_time_0`（`count` = 笔数，$n 取 0..count-1），**不是**申报接口那种扁平 `state`。解析必须带后缀；本项目无拆单，取第 0 条即当前记录（重复申报按文档是更新同一条，不会 count>1；若将来拆单要按 `modify_time_$n` 选最新）。
- **EXCEPT/FAIL 的排查线索在 `explanation_$n`**：申报异常的具体原因只在查询应答的 explanation 字段里。商户平台查询页看不到详情，且查询页「受理海关」必须选实际备案的那个海关（我们是「杭州（总署版）」）才查得到记录。后台订单详情「查询报关状态」按钮（GET /admin/orders/:orderNo/customs-declaration）就是干这个的。
- **已知的真实 EXCEPT 原因（2026-09-16 查明）**：「电商平台[5101960X8F]未按照海关总署179号公告要求完成跨境进口数据抓取平台的对接」——微信→海关通道本身已通（备案号/签名/身份校验 SAME 全过时出现此报错，说明不是配置问题），是平台企业未完成海关数据抓取平台对接（179 号公告：海关须能实时抓取平台订单原始数据做三单对碰）。属关务/商务动作（联系杭州海关/电子口岸杭州数据分中心），代码无解；且是订单/运单申报（OMS）共同前置条件。

## 配置口径（已确认事实，勿再反问用户）

- 海关备案以商户平台「账户中心 → 海关及商户信息」为准：**发送海关 = 杭州（总署版）→ `WXPAY_CUSTOMS_CODE=HANGZHOU_ZS`**；**备案号 `5101960X8F` → `WXPAY_MCH_CUSTOMS_NO`**（成都泽芃铭贸易有限公司，2026-09-11 已备案，2026-09-16 截图核对一致；义乌仓属杭州海关辖区）。
- 微信支持的海关枚举有限（GUANGZHOU_ZS / HANGZHOU_ZS / NINGBO / ZHENGZHOU_BS / CHONGQING / SHANGHAI_ZS / SHENZHEN / ZHENGZHOU_ZH_ZS / TIANJIN / ZONGSHU），列表没有的海关按文档在商户平台备案时选「广州（总署）」、调用时按备案信息传。
- 报关三要素（`WXPAY_API_V2_KEY` + `WXPAY_CUSTOMS_CODE` + `WXPAY_MCH_CUSTOMS_NO`）缺任一时 `isEnabled()=false`，调用方应跳过而非报错。

# 2026-09-12 微信支付联调避坑清单

> 读者：改动 `server/src/payments/`、`order.service.ts` 支付链路、退款/回调相关代码的 agent。
> 每条 = 规则 + 出处（真实踩坑）。改支付代码前逐条对照。新增坑用同格式追加到本目录新文件。

## 请求头

- **必须显式 `Accept-Language: zh-CN`**：Node 全局 fetch（undici）会自动补 `Accept-Language: *`，微信 V3 网关不认，`GET /v3/certificates` 回 `PARAM_ERROR 传入了不支持的Accept-Language`。已固化在 `wechat-pay.client.ts` request() 与回归测试。
- **公钥模式请求头带 `Wechatpay-Serial: <公钥ID>`**（微信文档要求，请求-应答场景）。已固化。

## 验签模式

- **新商户号没有平台证书**：`/v3/certificates` 回 `RESOURCE_NOT_EXISTS 无可用的平台证书` 是规定动作，不是故障。验签必须走微信支付公钥（`WXPAY_PUBLIC_KEY_PATH` + `WXPAY_PUBLIC_KEY_ID`，ID 为 `PUB_KEY_ID_` 前缀，两个变量必须成对配置，config 加载器已强校验）。
- 配了公钥后**不得再调 /v3/certificates**（`verifyNotification` 公钥分支直接本地验签，不触网）。
- 回调的 `Wechatpay-Serial` 在公钥模式下 = 公钥 ID，不匹配直接拒绝。

## 下单

- **同一 out_trade_no 重复下单，所有参数必须逐字节一致**（尤其 description），否则 `INVALID_REQUEST 商户订单号重复，但下单参数不一致`。**规则：支付参数一律从落库数据派生，禁止各调用路径各自传参**（事故：`create()` 传商品名、`getPayParams()` 缺省兜底文案 → 续付全部失败。修复：description 缺省时回取订单首个商品名，order.service.ts createPayParams）。
- 金额一律分；回调金额与本地订单不符必须拒绝 + 告警（handleWechatPaid 已做）。

## 回调

- 回调时间戳容忍窗 300 秒 → **服务器必须 NTP 校时**，时钟漂移会让所有回调被拒（日志特征：「回调时间戳超出容忍窗口」）。
- 验签/解密失败返回 4xx 让微信按节奏重推（15s/30s/3m/10m/30m/30m/1h/2h/6h…约24h），**不要让回调抛 500**。回调失败不丢单：重推 + 后台「查单补状态」（POST /admin/orders/:orderNo/sync-payment）双兜底。
- 回调处理幂等：同一 transactionId 重复推送直接返回成功。
- 回调 URL 必须公网 HTTPS，且在商户平台/代码 notify_url 一致。

## 验证方式

- 支付链路终验只能是**真实 0.01 元小额单**：单测/e2e 用注入 fetch 与内存仓储，覆盖不了微信网关行为。验收标准 = 不点补单按钮，订单自动从待付款转待发货。

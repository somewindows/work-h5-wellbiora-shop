# 生产部署顺序：build 必须先于 nssm restart

> 2026-09-18 实际踩坑。适用：每次服务器部署 server（NestJS 服务）。

## 现象

部署后后台新功能全部报 `Cannot GET /api/v1/admin/xxx`（404），但旧接口（登录、商品列表、/api/v1/home）一切正常，`nssm status` 显示 `SERVICE_RUNNING`，极具迷惑性——看起来像代码没部署上，实际是**服务在跑旧代码**。

## 根因

`nssm restart` 在 `npm run build` **之前**执行了。Node 进程只在启动时加载 `dist/`，build 完成后若不重启，进程继续跑旧包：旧接口能用、新接口 404。

## 排查方法（按此顺序，30 秒定位）

```powershell
# ① 新代码是否编译进 dist（看 LastWriteTime 是不是刚才 build 的时间）
Get-Item D:\www\wellbiora\repo\server\dist\users\admin-users.controller.js | Select Name, LastWriteTime

# ② 4000 端口被哪个 PID 占用
netstat -ano | findstr :4000

# ③ 该进程什么时候启动的——若 StartTime 早于 build 时间，就是它
Get-Process node | Select Id, StartTime, Path
```

进程 StartTime 早于 dist 的 LastWriteTime ⇒ 重启在编译之前，补一次重启即可。

## 正确顺序（铁律）

```
git pull → npm install → npm run migration:run → npm run build → nssm restart WellbioraServer
```

**重启永远是最后一步。** 前端同理：build 完再 robocopy 发布（静态文件无进程缓存，顺序不敏感，但保持一致习惯）。

## 备注

- 验证进程真的换了：重启后 `Get-Process node | Select Id, StartTime` 的 StartTime 应是当前时间，PID 应变化。
- 若重启后 PID/StartTime 没变，怀疑有手动启动的游离 node 进程占着 4000 端口：`Stop-Process -Id <PID> -Force` 后再重启服务。

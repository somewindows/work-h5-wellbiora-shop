# ICP 备案通过后上线推进手册（WELLBIORA H5 商城）

> 更新日期：2026-09-01  
> 使用方式：按阶段从上到下执行；每一项勾选后再进入下一项。涉及微信支付、海关和君梦的实际审核口径，以各平台当日后台提示和书面回复为准。

## 1. 先说结论：现在最紧要做什么

ICP备案通过，代表国内服务器可以合规承载这个域名；它**不等于**商城已经具备真实收款或发货能力。

当前项目的页面、登录、购物车、实名、下单等本地闭环已经可用，但支付和仓库接口仍是本地 mock：

- `server/src/orders/local-payment.adapter.ts`：仅返回 mock 支付参数；
- `server/src/orders/local-warehouse.adapter.ts`：只把现有商品视为有库存，不调用仓库；
- `GET /api/v1/auth/wechat-silent`：目前明确返回“微信静默授权尚未配置”；
- `server/docker-compose.yml`：目前只提供本地 MySQL，没有生产部署、Nginx 或 HTTPS 配置。

所以现在的主线是：

```text
已备案域名
  → 部署 HTTPS 测试环境
  → 配置公众号 + 微信支付 JSAPI
  → 拿到君梦测试环境和 SKU 档案
  → 开发并联调真实支付、报关、仓库
  → 小范围试单
  → 正式上线
```

**不要先做后台管理系统。** 现阶段只有 4 个 SKU，后台能后补；真实收款、三单对碰和发货能力才是上线的阻塞项。

## 3. 阶段 A：今天按步骤操作

### A1. 先确定域名与环境策略

建议先固定两个地址，不要在后续审核中频繁变更：

| 用途 | 建议地址示例 | 是否对消费者开放 |
|---|---|---|
| 正式商城 | `https://m.你的域名.com` 或 `https://你的域名.com` | 是 |
| 联调测试 | `https://staging.你的域名.com` | 否，仅内部 |
| 服务端接口 | `https://api.你的域名.com` 或与商城同域名下 `/api` | 否，供 H5 调用 |
| 微信支付回调 | `https://api.你的域名.com/api/v1/callbacks/wechat-pay` | 否，供微信服务器调用 |

操作：

1. 选定一个**正式 H5 域名**；不要只给根域名，先明确最终用户实际打开的完整地址。
2. 在域名 DNS 控制台添加正式和测试子域名的 A 记录，均指向国内服务器公网 IP。
3. 记录域名、服务器 IP、服务器登录方式、SSL 证书管理位置，并由负责人保存。
4. 访问工信部备案查询确认备案结果；正式站点上线时，在页面底部按要求展示备案号并链接至工信部备案查询站。

完成标准：

- 域名已解析；
- 团队明确“哪个是正式域名、哪个是测试域名”；
- 后续公众号、微信支付和回调一律以这套域名为准。

注意：ICP备案通过不自动包含公安备案、SSL 证书或微信平台白名单。这些仍需分别处理。

   - 确认账号类型是**服务号**；
   - 确认认证状态是已认证，并记下认证到期日；
   - 本项目已记录服务号为“泽芃铭Zevon”（`gh_75de7e368f9b`），仍以后台实际显示为准。

3. 确认管理员、运营人员和开发人员的微信号均可用；至少保留两名管理员，避免单人离职导致账号不可控。
4. 暂时不要配置网页授权域名：先等 HTTPS 测试环境部署完成后再配，避免来回改域名。

完成标准：服务号已认证、AppID 已记录在受控的密钥台账中、管理员可登录。

若未认证或认证已过期：立即发起微信认证；在此之前不要把 JSAPI 支付或微信静默登录排进可上线范围。

### A3. 核验微信支付商户号并开通 JSAPI

## 4. 阶段 B：部署 HTTPS 测试环境后配置白名单

### B1. 测试环境应达到什么状态

部署工作可以交由研发执行；上线前必须至少达到：

- 测试域名可从手机网络访问，浏览器地址栏显示 HTTPS；
- H5 静态资源与 API 都通过 HTTPS；
- MySQL 使用独立的测试数据库，不使用本机内存模式；
- 生产型随机密钥已通过服务器环境变量注入；
- 前端已关闭 mock，`VITE_USE_MOCK=0`；
- 服务端 `CORS_ORIGIN` 只允许测试商城域名；
- 不暴露 MySQL 的公网 `3306` 端口；
- 日志不输出身份证完整号码、支付签名、API 私钥或 `appSecret`。

本项目目前缺少生产部署编排和 Nginx 配置，这将是研发的首个实施任务。不要把本地的 `LOCAL_TEST_MODE=1` 当作测试服或正式环境。

### B2. 配置公众号域名

HTTPS 测试环境部署成功后，登录微信公众平台配置：

1. “设置与开发 → 公众号设置 → 功能设置”。
2. 填写**网页授权域名**，用于 `snsapi_base` 静默授权回调。
3. 填写 **JS 接口安全域名**，供微信内网页调用所需 JS 能力。
4. 按后台要求下载校验文件并放到网站根目录，使用浏览器访问确认可下载。
5. 保存设置后，在微信内打开测试商城，记录是否存在域名校验、重定向或授权错误。

重要限制：同一个服务号的网页授权回调域名通常不能同时兼顾多个无关环境。正式和测试环境策略必须预先确定：使用测试号联调，或让测试域名与正式域名采用可控的同域方案。不要在正式服务号上频繁切换，以免影响已上线用户。

### B3. 配置微信支付参数

在微信支付商户平台按实际菜单完成：

1. 设置支付授权目录，例如：`https://m.你的域名.com/`。
2. 在服务端配置支付回调地址：`https://api.你的域名.com/api/v1/callbacks/wechat-pay`。
3. 创建 API v3 密钥；将它存入服务器密钥管理或生产环境变量，不传给前端。
4. 下载商户 API 证书，记录证书序列号；私钥只保存在服务器受限目录。
5. 获取/定期更新微信支付平台证书，用于验证回调和平台响应。
6. 使用微信支付提供的测试工具或测试订单，确认域名、签名和回调连通。

完成标准：

- 微信能向回调地址发起 HTTPS 请求；
- 服务端能验签、解密并幂等处理回调；
- 前端仅拿到调起支付所需参数，绝不拿到商户私钥或 API v3 密钥。

### B4. 提交海关备案并申请自助清关

这是跨境支付单报关的前置事项，由商户平台负责人和仓库/君梦商务共同确认。

操作：

1. 在微信支付商户平台按要求提交海关备案信息；确认需要备案的海关及企业资料，以义乌保税仓实际报关口岸的书面回复为准。
2. 在“产品中心 → 自助清关”提交开通申请。
3. 记录申请单号、提交日期、审核状态、补件要求和负责人。
4. 确认财付通备案号 `4403169D3W` 与君梦下单参数中的 `payId` 一致。
5. 审核通过后，用测试订单验证支付单附加信息提交、查询和失败重推流程。

注意：海关处理的是订单、支付单、运单的三单信息匹配；真实消费者资金仍由微信支付按商户结算规则处理。综合税如何支付，必须以仓库/报关行合同为准。

## 5. 阶段 C：交给研发的实现顺序与验收标准

拿到上述资料后，研发不要一次性改所有模块，按以下顺序实施。

### C1. 生产部署与配置层

要做的改动：

- 增加生产 Docker/Nginx/HTTPS 部署方案；
- 分离开发、测试、生产环境变量；
- 强制生产环境设置 `JWT_SECRET`、`PERSONAL_DATA_KEY`、MySQL 连接信息和允许的 CORS 域名；
- 在反向代理场景评估并配置 NestJS `trust proxy`，确保短信 IP 限流取到真实客户端 IP；
- 建立数据库迁移、备份、恢复演练和日志轮转；
- 将 Nginx、应用、数据库权限最小化，数据库不暴露公网端口。

验收标准：服务器重启后应用能恢复；备份可还原到测试库；HTTPS 与 API 可访问；错误日志中没有敏感信息。

### C2. 微信登录和短信

要做的改动：

- 微信内浏览器：实现 `snsapi_base` 授权、回调换取 openid、openid 与手机号账户绑定；
- 微信外浏览器：继续使用手机号验证码登录；
- 将 `ConsoleSmsProvider` 替换为真实短信提供商实现；
- 保留并增强手机号/IP 限频、验证码失效、错误次数和风控；
- 前端按运行环境判断：微信内可尝试静默免登，失败后仍能走手机号登录。

验收标准：新用户可短信登录；已绑定 openid 的用户在微信内能免登；微信外浏览器不依赖微信授权也能完成登录。

### C3. 微信 JSAPI 支付

要做的改动：

- 新增真实 `PaymentAdapter`，替换 `LocalPaymentAdapter`；
- 创建本地待支付订单后，由服务端调用微信支付 JSAPI 下单并返回调起参数；
- 新增 `/api/v1/callbacks/wechat-pay`：验签、解密、幂等、持久化支付结果；
- 前端不以“用户支付后的页面跳转”判定成功，而是轮询订单或刷新订单状态；
- 实现未支付订单超时关闭、重复调起支付、退款与异常记录；
- 保留测试 mock，但只允许在本地开发环境启用，生产环境必须禁止 mock-pay 接口。

验收标准：同一支付回调重复投递不会重复改订单或重复推仓；订单支付成功的唯一可信来源是微信回调；退款有完整日志和状态。

### C4. 君梦 OMS 适配器

要做的改动：

- 新建君梦实现，仍只依赖 `WarehouseAdapter` 接口，不能把君梦字段散落到订单业务层；
- 所有请求在服务端签名，`appSecret` 仅存在服务端环境变量；
- 商品数据维护商城 SKU 到 `goods_no` 的映射；
- 下单前查库存；微信支付成功后才调用 `jm.order.bonded.add`；
- 保存君梦原始状态、请求结果和必要的脱敏排障日志；
- 定时轮询 `jm.order.bonded.get` 同步履约状态；
- 建立仓库发货回调入口，验签、幂等并触发状态收敛；
- 对“支付成功但推仓失败”建立可重试队列、人工处理清单和告警；不能静默丢单。

验收标准：一笔测试订单可完整看到本地订单号、微信支付单号、君梦批次/申报信息、仓库状态和物流信息；重复调用不会造成重复申报。

### C5. 跨境订单的不可省略校验

上线前需要通过自动化测试和人工用例共同验证：

- 收货人实名姓名、订单实名信息和支付人信息的三单对碰处理；
- 单笔订单不超过 5,000 元；
- 个人年度累计不超过 26,000 元；
- 身份证信息 AES-256-GCM 加密保存，页面只显示脱敏号码；
- 海关拒绝、库存不足、支付成功但推仓失败、已申报后取消、退款等异常路径；
- 订单取消只在允许窗口开放；已申报订单必须引导人工售后，不做错误的自动取消承诺。

---

## 6. 阶段 D：第一次真实试单怎么做

不要直接对公众开放。建议先完成 5 至 10 笔受控试单，再决定正式开放。

### D1. 试单前准备

- [ ] 测试人员均同意参与，并有可用身份证实名信息和微信支付账户；
- [ ] 选定一个有真实库存、价格和 `goods_no` 已确认的 SKU；
- [ ] 仓库商务确认测试单是否会真实出库、如何标记/拦截；
- [ ] 客服知道试单窗口和异常升级联系人；
- [ ] 已准备退款资金与退款处理人；
- [ ] 已确认不把测试单误当正式订单发货。

### D2. 每笔试单记录字段

建议用受控表格记录以下字段（身份证号和密钥不要放入表格）：

| 字段 | 示例/说明 |
|---|---|
| 本地订单号 | 商城生成的订单号 |
| 微信支付订单号 | 仅授权人员可见 |
| 君梦批次号/申报号 | 从 OMS 返回值记录 |
| 商品 SKU / `goods_no` | 用于核对映射 |
| 支付时间 | 用于核对回调时效 |
| OMS 接单时间 | 用于核对推单成功 |
| 仓库状态 / 物流单号 | 用于验证履约同步 |
| 异常与处理结果 | 必须留痕 |

### D3. 至少覆盖的试单场景

1. 正常支付、正常推仓、正常出库；
2. 用户支付后关闭页面，确认仍以服务端回调更新订单；
3. 重复点击下单或支付，确认不会产生重复订单/重复申报；
4. 支付成功但人为模拟君梦暂时不可用，确认进入重试和告警；
5. 未支付超时取消；
6. 已支付未申报退款；
7. 已申报订单的售后/退款人工路径；
8. 库存不足、限额、实名不一致的拒绝提示。

完成标准：每类场景都能给出对应订单记录、日志和处理结果；没有“钱已扣但订单查不到”或“订单已支付但仓库无记录”的未闭环情况。

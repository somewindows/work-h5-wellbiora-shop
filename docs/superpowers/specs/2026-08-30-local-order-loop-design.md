# 本地下单联调闭环设计

## 目标

在不接入微信支付和君梦 OMS 真实账号的前提下，提供可由 H5 前端直接操作、可由 NestJS e2e 测试覆盖的本地闭环：登录、购物车、地址与实名、订单预检、创建待支付订单、查询和取消。

## 范围与非范围

本阶段实现 `docs/tech/api-contract.md` 中的购物车、地址/实名和订单用户接口；首页、商品和认证沿用既有实现。微信与 OMS 保留服务端抽象，但不调用外部网络，也不生成或保存任何真实支付、仓库或短信密钥。

真实微信回调、微信退款、君梦签名和发货回调、后台 `admin/` 均不在本阶段实现；它们需要商户及 OMS 测试环境参数。本阶段的验收标准是本地 H5 能在 MySQL 数据库上完成待支付订单创建和取消，且自动测试覆盖关键规则。

## 数据与安全设计

新增 TypeORM 实体及迁移：

- `cart_items`：归属用户，保存 `product_id`、数量、勾选状态及创建更新时间；商品价格、名称和库存状态均在读取时以服务端商品目录重算。
- `addresses`：归属用户，保存收货人、手机号、省市区、详细地址、默认地址；创建首个地址时自动设为默认地址。
- `realname_profiles`：归属用户，保存实名姓名和 AES-256-GCM 密文身份证号；查询接口仅返回脱敏证件号，绝不回传明文。
- `orders` 与 `order_items`：订单保存地址、实名和商品的不可变快照；敏感证件号继续以密文保存。订单号、金额（分）、本地主状态、幂等键、支付状态、仓库状态和时间戳均由服务端生成。

`PERSONAL_DATA_KEY` 是 32 字节 Base64 密钥，只配置在 `server/.env`；`.env.example` 提供非生产占位值。服务端以 Node `crypto` 的 AES-256-GCM 加密身份证号，认证标签与随机 IV 一并保存。测试环境使用固定测试密钥，生产环境若未设置该变量必须拒绝启动。

## 鉴权与接口约束

新增 JWT 请求守卫，使用现有 `Authorization: Bearer <token>`。购物车、地址、实名和订单的所有用户接口均要求登录；认证、首页与商品接口保持公开。

接口维持 `/api/v1` 统一响应壳。订单取消状态统一使用前端既有联合类型 `cancelled`，并将 API 契约的 `cancel` 查询别名兼容映射为 `cancelled`，避免前后端状态值分裂。

## 订单业务流程

1. `POST /orders/precheck` 读取当前用户勾选的购物车、默认地址和实名档案，计算商品合计和应付金额（均为分）。本地测试阶段税费为 `0`，价格即含税示例价。
2. 服务端检查：至少一件已勾选商品、SKU 存在、数量为正、收货人姓名等于实名姓名、应付金额不超过 `500000` 分、当前自然年已申报订单累计加本订单不超过 `2600000` 分。
3. `POST /orders` 以 `requestId` 做用户维度幂等键，重做预检后在一个事务内写入订单、订单行并移除已结算购物车行，初始状态为 `pay`。重复 `requestId` 返回原订单。
4. 本地支付适配器只生成可展示的 mock 支付参数；订单保持待支付，前端跳转订单详情。开发环境单独提供受保护的 mock 确认入口供 e2e 使用，模拟支付回调；此入口在生产环境禁用。
5. `POST /orders/{orderNo}/cancel` 仅允许取消 `pay` 状态订单，状态变为 `cancelled`。已支付或已进入仓库履约的订单不允许本地取消，返回明确业务错误。

仓库访问由 `WarehouseAdapter` 接口承载；本阶段注册 `LocalWarehouseAdapter`，固定返回在售 SKU 有库存，且不调用外网。真实君梦实现以后替换注册实现，订单服务不依赖君梦字段或密钥。

## 前端联调设计

- 补全 `src/api/` 的地址 CRUD、实名保存、订单预检和取消函数；mock 路径同步保持当前页面可离线演示。
- 地址页保存时先写地址，再写实名；服务端最终校验收货人与实名一致，避免前端绕过。
- 结算页在创建订单前调用预检，显示服务端错误；创建成功后进入待支付订单详情。
- Vite 开发服务器添加 `/api` 到 `http://localhost:3000` 的代理。默认 `.env.development` 继续保持 `VITE_USE_MOCK=1`；提供本地联调说明，用户复制为 `.env.local` 并设为 `0` 后即可切换真实后端。

## 测试与验收

服务端单元测试覆盖：身份证密文往返与脱敏、购物车数量约束、订单限额/三单对碰/幂等/取消窗口、仓库 mock 适配器。e2e 测试覆盖完整的短信登录→鉴权购物车→保存地址实名→预检→创建订单→重复请求幂等→读取与取消订单路径。

前端 Vitest 测试覆盖新增 API 参数与关键页面决策；`npm run type-check` 与 `npm run build` 必须通过。最终在 MySQL 容器启动后，按 README 的手工测试路径用浏览器跑一次同样的闭环。
